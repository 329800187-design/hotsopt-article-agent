# 阶段二 2B.3.1.1：正文多图语义一致性精准修复验收报告

## 1. 本轮边界

本轮只修复正文多图的版本一致性、取消并发、索引同步、独立任务状态和恢复幂等。不进入 2B.3.2，不开发 Word、ZIP、编辑器、自动发布或授权码。

## 2. 四个缺陷及修复位置

1. **整篇重生成复用旧正文图**：`generation/single_task.py` 在整篇重生成时创建临时版本目录，并通过 `generation/inline_images.py` 的 `replan=True` 按新文章重新规划；新文章、封面和正文图全部成功后才替换正式版本，失败时恢复上一版本。
2. **取消被网络请求阻塞**：`generation/inline_images.py` 将 `task_lock` 缩小到状态读取、状态保存、取消检查和正式文件原子替换，Provider 请求在锁外执行。
3. **四处图片索引不同步**：`generation/inline_images.py::sync_inline_image_files()` 统一同步 `state.inline_images`、`state.article.images`、`article.json` 和 `images/assets.json`，并保持路径、元数据、尝试次数和回退标记一致。
4. **独立正文图操作状态不明确**：`generation/inline_images.py` 增加 `inline_operation`，操作期间进入 `running`，全部成功为 `completed`，部分或全部失败为 `partial_success`，并同步 SQLite。

## 3. 重启恢复

- `generating` 且正式文件不存在：恢复为 `failed`，错误码 `TASK_INTERRUPTED`，可重试。
- `generating` 且正式图片完整存在：重新校验元数据后恢复为 `completed`。
- 混合 `completed/generating/pending`：已完成图片不重复生成，中断图片转明确状态，待处理图片保留可执行状态。
- 连续执行两次恢复：第二次无恢复错误，未产生永久 `generating` 状态。
- `.attempts` 目录仅保存临时文件，不进入正文图片正式列表或普通页面。
