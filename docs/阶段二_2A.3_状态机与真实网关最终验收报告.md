## 本轮修改

- `generation/single_task.py`：允许 `failed/partial_success → cancelled`，取消立即同步 SQLite 与 task.json；完成态仍不可逆。
- `generation/recovery.py`：逐任务异常隔离，返回 `recovered`、`skipped`、`recovery_failed`；优先按 `failed_step` 恢复文章或封面重试；加入 SQLite/task.json 对账。
- `modules/database.py`：任务和 `generation_options` 改为同一个 INSERT 事务，保留旧数据库迁移兼容。
- `pytest.ini`：固定测试根目录为 `tests/`，避免扫描 `data/outputs/logs` 运行产物。
- `scripts/phase2a_live_smoke.py`：只读取本机配置，不含硬编码 API Key；无 Key 时报告待联调。
- `tests/test_phase2a3_state_machine.py`：新增状态机、恢复和事务专项回归。

## 状态证据

### 失败态取消

- `failed → cancelled`：`status=cancelled`、`stage=cancelled`、`cancellation_requested=true`、`next_retry_at=null`、`retryable=false`，SQLite 与 task.json 一致。
- `partial_success → cancelled`：同上。
- `completed → cancel`：返回 `TASK_ALREADY_COMPLETED`。
- `cancelled → cancel`：幂等返回 `cancelled`。
- 取消后 run/retry：返回 `TASK_CANCELLED`。

### retry_waiting 精确恢复

- `failed_step=generating_article` 即使存在旧 `article.json` 仍恢复为 `failed/generating_article`。
- `failed_step=generating_cover` 且文章有效恢复为 `partial_success/generating_cover`。
- `failed_step=generating_cover` 但文章缺失恢复为 `failed/generating_article`。
- 没有明确 `failed_step` 时才使用 `article_saved/generating_image_prompt/generating_cover` 阶段和文章有效性判断。

### 事务与对账

- INSERT 前异常：任务不存在。
- 参数序列化异常：事务回滚，任务不存在。
- 正常创建和重新打开 SQLite：`generation_options` 完整一致。
- JSON `completed/cancelled/failed`、SQLite `running`：SQLite 被修正，终态不降级。
- JSON 损坏：进入 `recovery_failed`，原文件不覆盖。
- JSON 缺失且 SQLite queued：重新初始化快照。
- SQLite 更新失败：本次进入 `recovery_failed`，下一次启动可再次对账。
