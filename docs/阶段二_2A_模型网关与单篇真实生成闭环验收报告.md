# 第二阶段 2A：模型网关与单篇真实生成闭环验收报告

## 1. 范围

本轮只实现模型网关、模型连接测试和单篇任务闭环：一个阶段一热点、一篇文章、一张封面。没有实现五篇批量、五角度、正文配图、在线编辑器、Word 精排、批量 ZIP 发布、自动发布、定时任务或多用户。

## 2. 现有框架审计结论

- 文本适配器原来已有 OpenAI 兼容 Chat Completions 请求和 JSON 解析，但缺少统一连接结果和标准请求对象。
- 图片适配器原来已有 URL/Base64 读取，但缺少 MIME、Pillow、尺寸、文件大小和 SHA-256 校验。
- 文章生成器已有生产模式拒绝 Demo 和 sections 校验，本轮复用并补充标题、事实依据、关键词、来源声明字段。
- 原编排器面向阶段一前置的批量演示流程，本轮未直接开放其五篇/多图入口，新增独立单篇运行器。
- 阶段一任务卡片已在 SQLite 持久化，本轮增加生成状态文件和结果目录，不破坏原任务表。

## 3. 主要修改

- `providers/contracts.py`：模型测试结果、文章请求、图片请求和适配器接口契约。
- `providers/text_provider.py`：统一鉴权方式、JSON 响应格式、连接测试、标准错误码和代理复用。
- `providers/image_provider.py`：URL/Base64 支持、真实图片校验、MIME/尺寸/大小/SHA-256 元数据。
- `modules/config_store.py`、`config/settings.example.json`：文本/图片配置结构补齐。
- `modules/generation_store.py`：原子保存和重启读取 2A 任务状态。
- `generation/single_task.py`：文章、提示词、封面、状态和重试的单篇闭环。
- `api.py`：模型测试、运行、结果、文章重试、封面重试和取消接口。
- `app.py`：2A 设置测试、单篇运行、进度、结果和重试入口。
- `tests/test_phase2a.py`：2A 专项自动化测试。

## 4. API

- `POST /api/models/text/test`
- `POST /api/models/image/test`
- `POST /api/tasks/{task_id}/run`
- `POST /api/tasks/{task_id}/retry-article`
- `POST /api/tasks/{task_id}/retry-cover`
- `POST /api/tasks/{task_id}/cancel`
- `GET /api/tasks/{task_id}/result`

所有接口继续使用阶段一统一响应和递归脱敏出口。

## 5. 结果目录

```text
data/tasks/<task_id>/
├── task.json
├── article.json
├── article.md
├── prompts/article_prompt.txt
├── prompts/cover_prompt.txt
└── images/cover.png
```

任务 JSON 只保存相对路径。模型公开信息只保留名称、地址、Endpoint、Model、鉴权类型、超时、尺寸和响应格式，不保存 API Key、完整 Header 或代理认证信息。

## 6. 状态机

```text
queued
→ generating_article
→ article_saved
→ generating_image_prompt
→ generating_cover
→ completed
```

文章失败进入 `failed`，封面失败进入 `partial_success`。封面失败时文章结果保留，`retry-cover` 不重新生成文章；文章失败时 `retry-article` 从文章阶段重新开始。完成任务拒绝重复运行。

## 7. 测试结果

执行：

```text
python -m compileall -q .
python -m pytest -q -p no:cacheprovider
```

结果：`88 passed, 1 warning`。其中阶段一基线 80 项，2A 新增 8 项，覆盖：

- 单篇文章/封面文件持久化与重启读取。
- 文章失败、封面失败和封面单独重试。
- HTML 错误页拒绝保存为图片。
- Bearer、X-API-Key、自定义 Header、无鉴权。
- 文本 JSON 连接结果和图片 Base64 连接结果。
- 2A 单热点单篇限制。
- 任务运行 API。

## 8. 真实网关验收边界

当前本机配置检查结果：文本 API Key 为空，图片 API Key 为空。真实第三方网关未执行成功调用，因此本报告不声称真实文章或真实封面已经生成。无 Key 时连接测试返回 `MODEL_NOT_CONFIGURED`，生产运行不会回退 Demo。

配置真实网关后，验收顺序为：分别测试文本/图片模型 → 创建一个文章数量为 1 的任务 → 运行任务 → 检查 `article.json`、`article.md`、`cover.png` 和提示词 → 重启后调用结果接口 → 人为制造封面失败并执行 `retry-cover`。
