# 阶段二 2A.2 僵尸任务恢复、参数持久化与真实网关最终收口报告

## 结论

2A.2 的代码收口和本机自动化验收完成。本轮没有进入 2B，没有开发五篇批量、五角度、正文配图、完整编辑器、Word 精排、自动发布或定时调度。

真实第三方文本和图片网关仍未 live 验收：本机 `config/settings.json` 没有文本或图片 API Key。模型连接接口实际返回 `MODEL_NOT_CONFIGURED`，因此本报告不把框架完成冒充为真实网关完成。

## 已完成

- 重试等待期间收到取消后，任务最终写入 `cancelled`，`next_retry_at` 清空，SQLite、`task.json` 和 Future 状态一致，且不会进行第二次模型调用。
- 新增 `recover_interrupted_tasks()`：启动和运行入口识别无活动 Future 的 `running` 任务；文章阶段恢复为 `failed/TASK_INTERRUPTED`，封面阶段在有效文章存在时恢复为 `partial_success/TASK_INTERRUPTED`。
- `cancellation_requested=true` 的任务恢复为 `cancelled`；`completed` 和既有 `cancelled` 不被恢复逻辑改写；不存在 SQLite 任务的状态文件被跳过。
- 统一进程内任务锁用于提交、取消、状态版本写入和恢复；模型网络调用期间不会阻塞取消请求。
- `generation_options` 通过 Pydantic 校验并写入 `generation_tasks.generation_options` 与生成状态快照；后台运行和重试读取持久化选项，不依赖 Streamlit session state。
- 任务卡片读取 SQLite 任务列表，并逐个请求结果 API，支持历史文章/摘要/正文/封面查看、取消和分阶段重试；完成任务只读。
