# 阶段二 2B.3.1：正文多图与单图重试闭环验收报告

## 1. 验收范围

本轮只交付正文多图规划、逐图生成、失败隔离、单图重试、批量重试入口、重启恢复和普通用户预览。不包含 Word、正文编辑器、批量 ZIP 导出、自动发布、定时调度、多用户或授权码。

## 2. 实现结果

- 正文图片数量为 2～4 张，按文章小标题生成稳定的 `section-1`、`section-2` 等 ID。
- 每张图片保存段落绑定、用途、提示词、状态、路径、尝试次数、错误码和图像元数据。
- 图片生成先写入任务目录下的 `.attempts` 临时目录，校验通过后原子替换正式文件。
- 单张失败不会删除文章、封面或其他成功图片；已有正式图片失败重试时保留上一版本。
- 服务重启后不会永久保留 `generating` 状态；中断图片会转为可重试失败状态。
- API 和普通页面均提供单图重试、重试失败图片和重新生成全部正文图片。

## 4. 失败隔离与重试

- FakeProvider 验证中间图片失败时，其他图片继续生成，文章保持可读。
- 单图重试只提交指定 `image_id`，文章文件、封面和其他正文图片哈希保持不变。
- 重试失败图片没有成功项时为空操作，不创建重复 Future。
- 批次子任务的 `failed_step=generating_inline_images` 使用正文图片重试路径，不重新生成文章。

## 5. API 与页面

- `GET /api/tasks/{task_id}/inline-images`
- `POST /api/tasks/{task_id}/inline-images/retry-failed`
- `POST /api/tasks/{task_id}/inline-images/regenerate`
- `POST /api/tasks/{task_id}/inline-images/{image_id}/retry`
- 普通“我的内容”页面展示正文图片和中文操作按钮；任务 ID、Provider、原始 JSON、traceback 和绝对路径不作为页面文案显示。

## 6. 安全与恢复

- 图片 ID 只允许 `section-数字`，拒绝路径穿越和任意文件访问。
- 中间文件失败时清理 `.attempts` 临时目录，正式文件保持上一版本。
- 任务状态使用现有原子 JSON 持久化、任务锁和执行器 Future 注册表。
- `python scripts/security_scan.py`：`SECURITY_SCAN_PASS`，无 forbidden hits。
